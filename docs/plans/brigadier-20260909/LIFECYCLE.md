# Lifecycle implementation evidence

Backend ownership delivered by lifecycle worker (2026-09-09).

- `src-tauri/src/composer.rs`: fsync+atomic durable drafts/queue/initial-send receipts with monotonic revisions. Serialized drain checks live provider Idle, preserves attachments, records sending before provider write, never replays unknown outcomes. Stop records intent and pauses before awaiting dispatch lock, cancels owned descendants, rescans creation races; explicit resume only. `project:<id>` draft scope supported. Commands catalog advertises only implemented app stop/context controls.
- `conversation_data.rs`: existing validated images/text extended with native path drop and generic binary attachments, capped 5 MiB. Original generic bytes persist in SQLite; sends export a local readable app-owned path and pass that reference via real provider text/tool path. No unsupported native file capability claim.
- `peers.rs` / `peer_sessions.rs`: independent worker model choice; explicit connected provider/effort schema, effective permissions inherited; root shared cap 8 live sessions; stopped caller/recipient dispatch gates; recursive child-only cancellation. Parent receives one passive owner-intervention notice. Completed worker read/wait triggers idle process retirement, non-forced workspace cleanup, retaining dirty work, branches and conversation history. `peers.retired` records outcome. Orchestration worker added rehydration from retained branch on resume.
- `state.rs` / `commands.rs`: persistent stopped-run identities across restart; initial owner creation stable `requestId` receipt, repeat acknowledged request returns existing session. Unknown request does not replay. Durable task memory initialized after session creation.
- `crates/store/src/chat.rs`, `feed.rs`, writer query additions: removed destructive 2000-item/turn history pruning; stable-ID incremental streaming append with seq replay guard and bounded 128-KiB bodies. `conversation_history_page` latest/backwards/incremental pages capped 100. Latest history render stays frontend bounded without deleting disk history.

Contracts: see composerApi.ts frontend adapter. History endpoint arguments `{sessionId,before?,after?,limit?}`, response `{items,nextAfter,nextBefore,hasMore}`. Composer notifications `composer-state` full state and `conversation-state-changed` session ID. Stop/context execute through `execute_composer_command`.

Checks: `cargo test -p brigadier --lib` passed 114 tests before task-memory/initial creation final integration; re-run by root after ongoing edits. `cargo test -p brigadier-store --test conversation_data --test history_pages` passed 5 attachment tests and paging test; binary attachment forwarding extended afterwards. History fixture stores 2100 bodies, exercises latest/backwards, repeated streaming delta once, and restart retention.

Known limits: actual connected provider is Claude only; unsupported providers rejected. No live paid provider smoke test from this worker. App command catalog only stop/context, no fake universal CLI commands. Queue drain uses provider/feed watch events plus 2-second fallback for missed notifications; actual transcript incremental UI owned by root. Cleanup is conservative: workers with uncommitted files retain their workspace. Initial uncertain creation requires inspecting existing conversations; no automatic retry.
