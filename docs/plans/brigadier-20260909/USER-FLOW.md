# Integrated Brigadier flow

Implementation: 2026-09-09. Scope: HANDOFF.md and the approved [composer redesign](../composer-redesign-2026-09-09.md). No publishing or deployment performed.

1. New tasks inherit the selected project and default to Auto + Approve for me. Both modes show the project/environment/branch rail before Send. New worktree + current files is the initial default; explicit choices persist per project and Auto respects them. Choose local, new or existing Git worktrees; existing entries show branch/path/active task and busy checkouts cannot be selected. Current, New branch and searchable Checkout choices are staged until Send. Current new worktrees inherit local changes; alternate branches start from committed state without silently stashing or discarding edits. Those setup choices lock after start and remain inspectable in Context.
2. Enter a goal in the rich composer. Markdown, grouped @ references to files/notes/agent sessions, literal code/path input and clipboard/drop/picker attachments are supported. Images show thumbnails; files show chips. Imports persist locally with per-file progress, retry and removal; any retained pending/failed import blocks Send. Large pastes become exact `.txt` attachments. Attachment-only initial requests are supported.
3. Send starts work. Rust retains task identity, displayed history and saved goal/decisions/results/verification across fresh native provider executions. Subsequent owner and peer dispatches receive bounded checkpoint/recent context and can retrieve additional saved state through tools. The whole displayed transcript is not copied into each new provider execution. This bounds context supplied by Brigadier; it does not impose a new hard tool-step/token ceiling inside an individual provider turn.
4. Enter while running queues a follow-up. Custom queue entries capture provider/model/effort; editing may change that snapshot. Auto resolves execution at dispatch. Steer now uses acknowledged Codex active-turn steering or Claude interruption followed by immediate fresh dispatch. Stop remains available during queue IPC, durably pauses dispatch/retries, cancels owned active work/descendants and preserves the draft and queue. Continue is explicit, including when the queue is empty. Uncertain delivery retains stable request IDs and requires resolution before retry.
5. Open Context for actual workspace changes/branch, Sources and workers. Subagents opens the existing right panel. Active/Done includes nested workers; opening one keeps the parent visible and provides the worker conversation, inline approvals and direct composer. Direct owner messages notify its orchestrator passively once. Cross-project worker files/attachments resolve in the worker's project/workspace.
6. Workers start from recorded task input snapshots, including covered local edits, with the parent index and HEAD unchanged. Finished idle workers can retire safely; unintegrated or dirty work is retained. Done history remains available, and Continue can reconstruct a removed disposable worktree from its retained branch.
7. The orchestrator integrates contributions, verifies acceptance and delivers results/diff/checks/unresolved issues. Interactive review/fusion uses real peer tools and durable checkpoints under the orchestration policy. The separate supervisor run loop additionally enforces bounded ordinary repair, isolated alternatives, independent reviews, meaningful gates and evidence-based selection. Prompt policy is not presented as a deterministic guarantee of every model decision.

## Controls and bounds

- A separate permission-style Auto/Custom picker stays in its existing position. Custom reveals an adjacent provider/model/effort picker; Auto hides it. Provider tabs use the assistant-ui SettingsPanel segmented source. The thick effort slider has actual supported steps, blue fill and a white thumb; Reset restores provider default, and unsupported effort is noninteractive. Model selection keeps it open. In Custom, changes affect subsequent work; provider changes appear as subtle inline dividers. Auto can be taken over once into Custom, inheriting effective settings; started Custom tasks cannot return to Auto.
- Per-project mode, permissions and manual setup choices persist separately from computed Auto routing. Existing tasks keep their own settings. Unavailable saved providers/models/efforts block Custom Send; unavailable or occupied workspaces and missing branches block both modes.
- Ask routes approval requests to the owner. Approve uses independent fresh authorization judgments against authentic owner instructions and escalates unsupported or conflicting evidence. Full suppresses permission prompts while retaining harness restrictions; exceptional unresolved permission requests are denied. Natural-language restrictions remain fallible interpretation, and native sandbox/hook coverage differs by provider.
- Approval cards are inline with tool actions. The Approval needed strip jumps to the card while preserving the draft. Only confirmed resolution folds a card; expired and failed responses remain distinguishable.
- Slash commands use advertised supported capabilities. Enter selects a suggestion; the next Enter submits. Unknown commands/arguments fail visibly. Routine compaction is not exposed as a durable-task lifecycle control. Native rewind and changing the settings of an already-running response remain unsupported.
- The composer responds to its own available width, including side-panel changes. Controls shorten then wrap, and popovers stay inside its bounds. No always-visible context-usage gauge remains.
- History opens latest-first, supports older pages and keeps a 600-item client window with bounded lifecycle metadata and virtual rows. Saved history is not deleted by that client bound. No unlimited-memory or comparative speed claim is made.
- Allowance is based on observed provider windows. Unknown remains unknown; explicit Stop takes precedence over reset. Codex reports tokens/windows, not dollar cost; its existing internal numeric cost sentinel is not a billing estimate.
- Images and opaque files are limited to 5 MiB, UTF-8 text to 1 MiB, and each message to 20 attachments. Original file access does not imply the provider understands every file format.
