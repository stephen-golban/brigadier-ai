# Fixed-window onboarding

The first Continue still flickered because the preceding implementation moved native resizing and titlebar restoration from the greeting to that button. It also rebuilt the WebGL program when the cinematic stage changed. Both operations have been removed.

The app now configures one normal decorated window while hidden, then shows it. The intro, name form, greeting, workspace, replay, and reset use that same window. No onboarding command changes its geometry, decorations, backing surface, or visibility. The intro now plays inside the final app frame, rather than expanding over the desktop. The existing alpha-capable webview is retained, with the onboarding and workspace painting their own opaque backgrounds throughout the transitions.

First Continue saves progress while keeping the welcome visible, then fades the welcome out over 200 ms and the name form in over 280 ms after a 120 ms delay. Name entry stays inert and explicitly disabled until its animation finishes. The WebGL canvas and compiled program survive stage changes; only uniforms change. Workspace loading starts after the name fade, avoiding initialization work during this transition. Reduced motion enters name entry directly. The greeting still waits for workspace readiness and its minimum hold, then fades into the rendered app.

Reset clears the name and onboarding flags without restarting or resizing the window. Projects, notes, and unrelated preferences are preserved. The name validation, arrow handling, shadcn input, reset buttons, shorter intro audio, and removal of the returning-startup sound remain in place.

Validation: 44 targeted frontend tests and four native launch tests passed. The final input-gating adjustment also passed the 23 relevant launch/style tests and TypeScript build. Browser integration sampled 51 first-Continue frames with a retained canvas/program and unchanged bounds, plus 62 greeting/workspace fade frames. Profile persistence, reset from both locations, name filtering/navigation, replay, mute, and reduced motion passed. Native installed-app verification is recorded below separately.

Installed release at `/Applications/Brigadier.app`, signed and signature-verified. Backup app/preferences: `~/Library/Application Support/Brigadier-update-backups/20260907-152611-fixed-window`. Native capture showed unchanged window framing, but CSS and requestAnimationFrame animation did not advance reliably during the capture session, with either opaque or the original alpha-capable webview configuration. Native frame-by-frame smoothness remains unverified; browser frame sampling is not claimed as native proof. The final observed native state was the normal workspace with the saved Stephen profile; no further reset was performed after that observation.
