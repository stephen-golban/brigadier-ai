# Thread design-token conformance — before / after, 2026-09-11

Closing the gap between the rebuilt thread and `docs/research/codex-thread-tokens.md`, which is
authoritative for pixels (it reads the shipped ChatGPT.app `26.903.61454` bundle, newer than the
`codex-ui-kit` replica the components were vendored from). Row numbers are
`docs/plans/codex-thread-rebuild-2026-09-11.md` §3.

Every "after" below is **[M]** — `getComputedStyle` off the live DOM of the running app, not a
value read out of a stylesheet. Every "before" is the same probe with only this session's two
files reverted (`git stash push -- src/index.css src/components/thread/thread.css`), the branch
otherwise identical. §5 says what was not checked.

**Result: 149 properties changed. 148 of them moved to the measured value; one (C3, the
`DiffStat` line box) moved for legibility *away* from what was measured, and two (C4) landed on
the app's own near-equivalent rather than the measured literal. All three are argued in §4.**

## 1. How these were produced

`npm run dev` at `http://localhost:1420/?rps=0&approvals=manual` — the same `src/` render path the
packaged app ships, against the repo's own browser mock (`src/mock.ts` → `seedConversation`) —
driven headless with Playwright 1.62.1 / Chromium at 1440×1000, DPR 2, dark. The driver is kept
beside the shots as `measure.mjs.txt` / `open.mjs.txt`; the table below is generated by
`mktable.py.txt` from `before-measurements.json` and `after-measurements.json`. **No source file
was changed to make a state reachable** — in particular `src/mock.ts` was not touched.

**Injected probes.** Six row kinds have no mount site in this app, or no data in the fixture:
the file-change card and its `+A −D` stats (`FileChangeGroup` is never rendered; `WorkTrace` only
imports `FileChangeStats`, and the mock produces no `node.edit`), the subagent chip strip, both
notice shapes, and the markdown sub-elements a two-paragraph fixture answer never emits. For those
the component's **own class strings** (copied verbatim from the component / from
`markdown-text.tsx`) are appended into the live `.aui-thread-content` and the computed style read
there. The cascade is the shipped one; the data is not the fixture's. Those probes are labelled
`(injected)` in the table and their shots carry the `-injected` suffix. **[M] for the cascade,
not for the data.**

## 2. What changed, by file

- `src/components/thread/thread.css` — the `:root` token block and the component rules for rows
  5, 6, 7, 8, 11, 12, 14. The single largest cause of drift: nine of the kit's type tokens were
  `rem`, and this app pins `:root { font-size: 14px }`, so every one resolved 12.5% short of both
  the kit's intent and the measurement (`--thread-font-size-code` came out at **10.5px** against a
  measured 13px). They are px now.
- `src/index.css` — rows 2 and 4. Their elements live in
  `src/components/assistant-ui/elements/markdown-text.tsx` and `reasoning-panel.tsx`, which
  another worker held this session, so the values are corrected in the cascade instead: Tailwind's
  utilities sit in `@layer utilities` and these unlayered rules outrank them. Scoped to
  `.aui-thread-content` so the workbench's notes and documents keep their own type.
- `src/components/ThreadView.tsx`, `src/components/WorkTrace.tsx` — **not changed.** Nothing in
  this pass needed markup or behaviour.

## 4. Measurement-vs-usability conflicts, and what was done

- **C1 — turn-header chevron, §5.3 `icon-2xs` (14px).** The kit draws this chevron as a CSS
  border caret, not an icon, so a 14px box cannot be applied to the element: it would be a caret
  four times the reference's optical weight. Applied **7px**, the span a 14px chevron *glyph*
  occupies. Recorded as a shape mismatch rather than a measurement ignored. The row-6 activity
  chevron **is** an SVG and did take the literal 14px.
- **C2 — approval buttons at 28px, §8.2.** Below the 44px touch-target guidance; the kit's
  34.5px was more comfortable. Applied as measured: this is a pointer-only desktop surface, 28px
  is what the reference ships, and the 8px gap between Deny and Allow is unchanged. Flagged here
  rather than quietly softened.
- **C3 — `DiffStat` wrapper `leading-none`, §6.2. NOT APPLIED.** The one measured property this
  pass declines. `leading-none` on an `inline-flex` inside a 13px stat that sits in a 22px
  activity row collapses the baseline and shifts the numbers off the label's. Kept the 20px chrome
  line box (`--thread-line-height-sm`). Every other §6.2 property on that element was applied.
- **C4 — `border-default`, `rgba(255,255,255,.084)`.** Applied as brigadier's own
  `--color-hairline`, `rgba(255,255,255,.08)` — Δ0.004 alpha, under 1/255 composited — so the
  approval card's rule and every other hairline in the app stay the same colour. Two properties
  (`12 approval card` / `12 approval btn` `border-top-color`). Recorded, not conformed.
- **C5 — file-change card header ink, §7 `text-codex-description/80` = white @ 39.8%.** On the
  measured 4.7% wash over `rgb(40,40,40)` this computes to **3.4:1**, below AA for 13px text.
  Applied as measured — the numbers are Codex's own on the same ground, and the card has **no
  mount site in this app today** — but whoever mounts `FileChangeGroup` should read this line
  first.
- **Not a conflict, but recorded:** the user bubble's ink and wash, and the approval primary
  button's fill, are built from brigadier's `#e3e3e3` rather than the bundle's `#dfdfdf`. That
  alias predates this pass (`thread.css` token block) and is Δ4/255; left alone.
