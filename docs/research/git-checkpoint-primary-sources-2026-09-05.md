# Git checkpoint storage: primary-source review

2026-09-05. Independent research for the Brigadier checkpoint design; **no production implementation**. Responsible verifier: the implementing engineer and owner before enabling workspace restore. Official documents fetched today; installed Git measured as `git version 2.50.1 (Apple Git-155)`. Current online manuals include later Git releases, so flags used below were also exercised locally where marked measured.

## Recommendation

**[Proposal] Use a separate, app-owned bare snapshot repository outside the source checkout, one store per canonical workspace identity, with raw blobs, fresh alternate indexes, trees and explicit retained refs.** Keep the user's index, HEAD, branches, refs and object database untouched. The app's own SQLite journal owns message association, completeness and transaction state; Git supplies content addressing and storage. Do not use the owner's object database through alternates. This has an initial storage cost but gives independent lifetime, maintenance and privacy boundaries.

**[Measured] “Private” refs in the user's repository are not private storage:** a local `git push --mirror` exported a fixture `refs/brigadier/checkpoint` pointing directly at a tree. The ref was also visible from its linked worktree. Both follow official Git behavior. Separate storage avoids accidental export through source-repository mirroring; it is not encryption or a security sandbox.

## Evidence matrix

| Question | Verified documentation | Measured here / design consequence |
|---|---|---|
| Alternate index | `GIT_INDEX_FILE` selects an index instead of the default; `GIT_DIR`, object directories and common-directory variables have independent effects. [git environment](https://git-scm.com/docs/git#Documentation/git.txt-codeGITINDEXFILEcode) | Snapshotting a staged-plus-unstaged fixture left the real index byte-identical and HEAD identical. Environment isolation must cover more than `GIT_INDEX_FILE`. |
| Exact bytes | `hash-object --no-filters` ignores attribute input filters and line-ending conversion. Stdin implies this unless `--path` is supplied. [hash-object](https://git-scm.com/docs/git-hash-object) | CRLF raw hash differed from normal hash; raw `cat-file blob` roundtrip matched bytes. A custom clean filter also changed the normal hash. |
| Tree construction | `update-index --index-info` accepts mode/OID/path records; `-z` makes path delimiters NUL. [update-index](https://git-scm.com/docs/git-update-index) `write-tree` uses the index, requires a fully merged index and normally checks referenced objects exist. [write-tree](https://git-scm.com/docs/git-write-tree) | Fresh stage-0 entries produced a tree for working bytes, independently of the user's staged version. Do not copy a conflicted or sparse source index as the snapshot's representation. |
| Files and metadata | Index entries support regular files, symlinks and gitlinks; regular-file modes are 0644 or 0755. Normal index entries do not record directories. [index format](https://git-scm.com/docs/gitformat-index) | Tree listed empty file, binary-with-NUL file, symlink mode 120000 and executable mode 100755. Empty directory was absent. Empty directories and metadata beyond Git modes need an app manifest or explicit unsupported capability. |
| Linked worktrees | HEAD and index are per-worktree; most refs are shared, except `refs/bisect`, `refs/worktree`, `refs/rewritten`. Resolve repository paths with `rev-parse --git-path`. [worktree](https://git-scm.com/docs/git-worktree#_details) | Linked fixture observed the same custom checkpoint ref and a different index location. A worktree does not isolate every repository mutation. |
| Publishing exposure | `push --mirror` mirrors all refs beneath `refs/`, beyond branches and tags. [push](https://git-scm.com/docs/git-push#Documentation/git-push.txt---mirror) | Local bare mirror received the checkpoint tree ref. Namespace naming is insufficient to protect ignored/uncommitted data from export. |
| Retention | `gc` retains objects reachable from `refs/*`, indexes and reflogs. Notes attached to an object do not retain that object. Concurrent writers and pruning can race. [gc](https://git-scm.com/docs/git-gc#_notes) | A referenced bare-store blob survived `gc --prune=now`; deleting its ref then repeating GC removed it. Maintain explicit roots and serialize maintenance with snapshot writers. |
| Ref transaction | `update-ref --stdin` supports `start`, `prepare`, `commit`, `abort` and old-OID checks. A failed lock/value check prevents all queued updates, but concurrent readers may observe a subset during successful updates. [update-ref](https://git-scm.com/docs/git-update-ref) | Wrong old OID on one of two updates: exit 128, both unchanged. Correct old OIDs: exit 0, both updated. This is not an atomic transaction across SQLite, files and provider conversation. |
| Filters on restore | `cat-file blob OID` returns object content; `--filters` requests smudge and line-ending conversion. [cat-file](https://git-scm.com/docs/git-cat-file) Filters may execute commands or a long-running process. [attributes](https://git-scm.com/docs/gitattributes) | Prefer raw object extraction and app-controlled writes. Avoid checkout paths that reapply attributes when restoring raw snapshots. |
| LFS | LFS clean stores content separately and emits a pointer; smudge resolves a pointer locally or downloads its object. [Git LFS specification](https://github.com/git-lfs/git-lfs/blob/main/docs/spec.md#intercepting-git) | **Not measured with Git LFS.** Raw snapshots should preserve whichever bytes are materialized, whether content or pointer, with no hydration/download. This can duplicate large LFS materializations; quotas are required. |
| Hooks/config | Reference transactions can invoke hooks. [hooks](https://git-scm.com/docs/githooks#_reference_transaction) `init` copies templates; `--template` selects the source; bare creation and permission options are documented. [init](https://git-scm.com/docs/git-init) | **Proposal:** dedicated empty template/hooks directory, restricted permissions, controlled config and scrubbed Git environment. Separate storage alone does not neutralize inherited global config. |

## Measured experiment record

All mutations occurred in new temporary repositories. No model calls, owner-repository staging/commits, pushes or cleanup occurred. The only push was between two temporary local repositories.

Fixture A: `/var/folders/1g/t85z95812fqc1lstp9cvy9mr0000gn/T/brigadier-git-docs-ubwy4uhz`.

1. Initialized `repo`, committed `a.txt=baseline\n`, staged `a.txt=staged\n`, then wrote `a.txt=working\r\n` without staging. Added text/eol attributes, custom clean/smudge filters replacing `SECRET`/`POINTER`, a binary file containing NUL, empty file/directory, symlink and executable.
2. Saved the actual index bytes and HEAD. Set `GIT_INDEX_FILE` to a new file outside `repo`; ran `read-tree --empty`; enumerated fixture entries with `lstat` semantics. For symlinks, hashed the link target string; for regular files, hashed bytes through `hash-object -w --no-filters --stdin`. Fed `mode SP oid TAB path NUL` through `update-index -z --index-info`; ran `write-tree`.
3. Produced tree `3c6356262a87662700c78cbae641a66fe5f714be`; actual index and HEAD matched their saved values. Tree modes included `100644`, `100755`, `120000`; six files, no empty directory. `cat-file blob TREE:a.txt` equalled the source bytes.
4. Set `refs/brigadier/checkpoint` to that tree, pushed `--mirror` to temporary `mirror.git`; target ref matched. Created a detached linked worktree; custom ref matched, index location differed.
5. In a separate temporary bare `snap.git`, retained a blob with `refs/checkpoints/retained`. `gc --prune=now` kept it; deleting the ref and repeating GC made `cat-file -e` fail. This destructive GC was confined to disposable data and is **not** a recommended production maintenance command.

Fixture B: `/var/folders/1g/t85z95812fqc1lstp9cvy9mr0000gn/T/brigadier-ref-txn-ridbfesa`.

Two refs started at blob A. Sent `start`, two `update REF B EXPECTED`, `prepare`, `commit` via `update-ref --stdin`. One EXPECTED=B caused exit 128 and preserved both A values. Repeating with both EXPECTED=A returned 0 and both B values. The test checks validation atomicity, not crash durability or simultaneous reader visibility.

## Proposed storage contract and traps

- **Identity and retention:** key stores by stable app workspace ID plus canonical root/repository/worktree identity; detect path replacement. Give every retained checkpoint/recovery tree an explicit ref. Keep parents out of checkpoint commits, or use direct tree refs, so deleting one checkpoint does not implicitly retain every ancestor through a commit chain. SQLite metadata alone cannot keep Git objects alive. No object alternates to the source repo: its GC or removal must not destroy recovery data.
- **Full inventory, bounded scope:** enumerate the covered filesystem independently of successful tool records and source-index flags. Include tracked and allowed untracked files; define ignored/excluded-file policy explicitly. A changed exclusion policy changes checkpoint coverage and must not be mistaken for file deletion. Never traverse `.git`, nested repository metadata or symlink targets; excluded, unreadable, oversize or special files produce explicit capability/completeness data. Do not promise all-workspace restoration when something was skipped.
- **Raw-byte preservation:** compare raw OID, type and executable mode, not Git porcelain status or line counts. Binary changes, identical rewrites and changes later undone are representable. Renames are an optional presentation heuristic over deletion/addition, not the restore identity. Preserve actual raw bytes for line endings, encoding and LFS materialization. Exact permissions, ACLs, xattrs, hardlink topology and empty directories are outside a plain Git tree contract.
- **User Git state:** never restore the whole source index merely to restore files. Preserve current index/HEAD/branch unless an explicit Git-state undo feature is designed. Capture source Git state/fingerprints to detect provider commits, checkout/branch changes, staging and conflict transitions; initial release should block automatic file rewind when those transitions make the intended baseline unsafe. A file restore can otherwise create a dirty inverse of provider commits rather than undoing those commits.
- **Concurrent writers:** neither an alternate index nor a Git ref transaction freezes the filesystem or attributes writes to an actor. Before/end checkpoints only prove observed states. Require a supported single-writer/quiescence contract for automatic restoration, and compare live affected paths with expected span-end values immediately before applying. Unrelated paths remain untouched; affected paths with later manual edits require conflict handling. No finite precheck eliminates a writer racing after the check. Inter-turn manual edits also require composition of per-turn deltas rather than restoring the oldest whole tree.
- **Transactions:** durably retain recovery data and planned per-path before/after values before any destructive restore or native conversation operation. Journal provider intent/result separately from file-application progress; unknown provider outcomes block sends. Ref validation provides one component, not the transaction. Crash recovery must reconcile current path bytes and durable journal before proceeding; successful process exit alone has not been power-loss tested.
- **Maintenance/security:** restrict snapshot access; never configure remotes. Disable inherited hooks and external transformations for object operations; use raw OID reads. Apply quotas before accepting a checkpoint as complete. Serialize pruning with writes/recovery; deleting refs is retention-policy work, and GC is a separate maintenance phase. Time/size benchmarks, disk-full behavior and deletion latency are not measured here.

## Required follow-up acceptance tests

**[Proposal, not executed here]** Add tests for raw roundtrips under changing `.gitattributes`, malicious clean/smudge/reference hooks, embedded NUL bytes, newline/tab/non-UTF-8 names, file↔directory↔symlink transitions, sparse/source-conflicted indexes, submodules/nested repositories, branch switches/commits, ignored-policy changes and large LFS files. Verify source index bytes, HEAD and refs remain unchanged by capture and normal file restore. Exercise stale preview, same-path manual changes, background writers, partial apply, app crash between each durable phase, disk full, missing/corrupt objects and GC racing capture. Confirm unchanged-text resubmission and net-zero covered workspace changes bypass confirmation only when checkpoint coverage is sufficient. Provider-native rewind verification and exact Brigadier module integration are owned by the main report, not established by these Git-only experiments.
