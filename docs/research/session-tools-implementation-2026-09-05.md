## Implemented

**[source]** `ThreadView`, `EditMessage`, `sessionApi`, `conversation.rs`, and the core native-control boundary implement editing an earlier human message through Claude's native `rewind_conversation`. New outbound human messages carry explicit UUIDs; the display projection stores those UUIDs independently of the local item ID. Legacy messages without verified UUIDs are capability-gated. The installed 2.1.261 is the verified conversation-rewind version; other versions are gated rather than assumed compatible. See [provider capability research](rewind-context-2026-09-05.md).

**[source]** Editing now uses the dock’s existing `PromptInput`. `App` passes the selected message from `ThreadView` to `Dock`; a keyed composer keeps the edit separate from the unsent regular draft. Cancel restores that draft. `useMessageEdit` preserves edited text on refusal/send failure and never sends it before native rewind succeeds. Sending after a successful rewind can be retried without rewinding twice. The native request carries the latest observed human UUID and refuses an active turn. The adapter holds a send barrier until local persistence finishes. Semantic refusals retain visible history. The success UUID must match the target, and the local cut uses the adapter's response-time sequence boundary. Late queued rows from the discarded range are archived instead of reappearing.

**[source]** Store migration 7 (database version 8) adds verified provider UUIDs, a durable pending/applied/refused rewind journal, and archived message bodies. The archive is written and flushed before mutation. Saved history exposes recent operations and paged, copyable original bodies. Timeout, EOF, unrecognized response, or an unconfirmed disk write leaves a pending record and blocks sending/resuming. A pending outcome requires manual reconciliation; there is no safe automated reconciliation flow. The native provider has no verified read-only live conversation API, and its SDK historical getter ignores rewind anchors. See the research note's measured restart test.

**[source]** File restoration remains unavailable; the backend rejects combined scope. The edit flow no longer presents a scope chooser. Claude's dry-run can omit files that actual restoration touches, while persisted file-history snapshots can lag or fail to write. Neither is a complete preview or recovery inventory. Therefore no native file restore is executed, no Git reset is substituted, and checkpointing is not newly enabled. This is a provider-interface limitation, not a claim that Claude has no file-rewind feature. Shell effects and ordinary subagent edits are outside its checkpoint coverage.

**[source]** `SessionContext` polls `get_context_usage` with `detail:summary`, reports a provider estimate, and computes occupancy from current `totalTokens/maxTokens`, never lifetime usage. Unknown/invalid/missing telemetry produces a dash, not zero. Session changes and compaction/turn/rewind revisions refresh the sample. Detail disclosure shows token count, limit, model and sample time. Busy sessions poll every eight seconds; idle sessions every thirty seconds.

**[source]** `AgentsPanel` reuses project sessions, peer titles/origins and existing navigation. It shows actual CLI/provider/instance/model and native main-session status. Child task lifecycle comes from task_started/progress/updated/notification events; child model is only filled by a correlated assistant model observation. Unknown stays unknown. Main action text comes from observed tool calls, and past action is labeled Last. Only the expanded panel polls local adapter activity; that query does not make a provider/model request. Codex and other integrations are not claimed as connected.

**[source]** Copy actions cover human and assistant messages, disclosed progress, tool inputs/outputs, and saved history. Clipboard errors have an accessible retry label; copied state resets on content change and after two seconds.
