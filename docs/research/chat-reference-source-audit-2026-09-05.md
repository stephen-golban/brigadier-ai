# Chat composer, thread widgets, and workspace panel: source audit

Date: 2026-09-05. Scope: current public T3 Code and Jan source, inspected for Brigadier's requested local-only agent chat. This supplements the older `t3code.md` and `jan.md` notes; their line numbers and current-state claims should not be assumed to match these revisions.

**Recommendation:** use T3 Code's provider capability contracts and workspace surface model as architectural references; use Jan's reasoning, tool, question, and artifact components as interaction references. Build Brigadier's implementation around its own bounded event pipeline. The screenshots establish the desired appearance and controls; public source establishes implementation patterns, not the internals of ChatGPT or Devin.

## 1. T3 Code: capability-driven composer

The useful abstraction is a provider/model descriptor contract. An option has an ID, label, optional description, and either select choices with default/current values or a boolean current value. A model carries `optionDescriptors`; selected values are separate `{id, value}` records. This makes effort, speed, context, and agent-specific settings data rather than hard-coded rows of controls. [Contract](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/packages/contracts/src/model.ts#L7).

The UI still has intentional presentation rules: `TraitsPicker` distinguishes primary effort, `contextWindow`, `agent`, `fastMode`, and `thinking`. Therefore it is better described as **generic contracts plus curated rendering** than as a schema form generator. Missing OpenCode model metadata produces read-only descriptors from saved values, preserving what the user previously selected. [Traits selection](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/chat/TraitsPicker.tsx#L45).

Selection normalization checks known choices and falls back to the current/default choice when the saved choice is invalid. The composer computes explicit dispatch selections from the resulting descriptors; it also handles provider-specific prompt-injected effort as a distinct case. **For Brigadier:** detect capabilities from the installed CLI/session, retain settings per agent and thread, validate on model changes, and pass actual supported values to the adapter. A button that changes only UI state is not feature parity. Screenshot model names should be reference data, never a permanently hard-coded catalog. [Normalization](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/packages/shared/src/model.ts#L75), [dispatch projection](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/chat/composerProviderState.tsx#L66).

Permissions and planning are independent: `RuntimeMode` is approval-required / auto-accept-edits / auto / full-access, while interaction mode is default / plan. **For Brigadier:** preserve that conceptual separation even if Claude presents Plan alongside permission modes. Do not assume superficially similar Codex and Claude permission labels have identical semantics. [Mode contracts](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/packages/contracts/src/orchestration.ts#L120).

The editor is Lexical with plain-text and history plugins, plus atomic decorator nodes for file mentions and other context. It manages caret offsets across display/expanded text and composition events. The larger composer owns attachment preparation, validation, paste/drop, command menus, terminal context, review comments, and submission. Draft persistence is debounced at 300 ms. **For Brigadier:** use an editor abstraction that can represent context chips without corrupting selection, undo, IME input, paste, or Enter/Shift+Enter behavior. Keep the draft and submit transaction outside the editor component. [Editor](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/ComposerPromptEditor.tsx#L1), [composer](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/chat/ChatComposer.tsx#L1), [draft store](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/composerDraftStore.ts#L67).

Narrow layouts get compact footer controls; explicit breakpoints are 620 and 780 px. **For Brigadier:** size the composer against its actual column width, since opening the requested side panel substantially shrinks it. An unchanged desktop toolbar will overflow. [Footer layout](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/composerFooterLayout.ts#L1).

## 2. T3 Code: transcript is a projection, not the raw event log

The canonical contract separates messages, proposed plans, session status, checkpoint file summaries, activities, and latest-turn status. Activities carry stable event IDs, turn IDs, optional sequence, tone, summary, and payload. Messages carry IDs, text, attachments, turn association, streaming flag, and timestamps. **For Brigadier:** adapters should normalize native CLI events into typed records once; renderers should not parse CLI-specific payloads or infer tool identity from prose. [Canonical records](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/packages/contracts/src/orchestration.ts#L351).

A second projection turns those records into UI rows: message, assistant metadata, work, live work, work disclosure, turn fold, context compaction, proposed plan, working, and thinking. Work disclosures include hidden count, summary, expansion state, and failure state. This is the mechanism behind a quiet transcript with expandable detail. **For Brigadier:** store raw evidence separately from the presentation model; one tool call should update one stable item, not append a new visual row for every delta. [Timeline row union](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/chat/MessagesTimeline.logic.ts#L282).

The main list uses LegendList with stable keys, item types, estimated heights, end-follow and visible-position behavior. Expanded tool groups also get a bounded virtualized list. Individual expanded tool bodies have a bounded scroll area and deduplicate command/detail/file content. **For Brigadier:** retain virtualization when adding rich cards, and preserve the reader's scroll anchor when cards expand. A fixed-height text row assumption cannot simply be retained for arbitrary Markdown and panels. [Main list](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/chat/MessagesTimeline.tsx#L764), [expanded groups](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/chat/MessagesTimeline.tsx#L1739), [expanded tool body](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/chat/MessagesTimeline.tsx#L2932).

Approvals are actual suspended operations: Claude's `canUseTool` emits a request with a stable request ID, holds a deferred response, handles abort including the already-aborted race, then emits request resolution. AskUserQuestion uses a separate user-input path; ExitPlanMode captures a plan. **For Brigadier:** approval/question cards need pending/resolving/resolved/cancelled state and a transport response contract. They cannot be decorative widgets. [Claude request lifecycle](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/server/src/provider/Layers/ClaudeAdapter.ts#L4425).

## 3. T3 Code: a workspace panel composed of surfaces

`rightPanelStore` owns thread-scoped ordered surface descriptors and the active surface. Each feature owns its durable resources. Files point to paths and line-reveal requests; terminals point to session IDs and can contain splits; previews point to browser resources. File tree, diff, and agents are singleton kinds. The panel persists descriptors separately from the resources. **For Brigadier:** copy this ownership boundary; toggling or unmounting the panel must not accidentally terminate a terminal or erase a draft. Remove environment identity/remote connection machinery for the explicitly local-only product. [Surface model](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/rightPanelStore.ts#L1).

The tab shell exposes add files/diff/terminal/browser/agents actions, individual availability reasons, close/close-others/close-right/close-all, and persisted width through its shell. **For Brigadier:** implement one resizable tab host with Files, Changes, terminal tabs, and file tabs; future widgets can request a surface through a small command API. [Tabs contract](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/RightPanelTabs.tsx#L66).

The file browser uses `@pierre/trees`, tracks selection/reveal independently, supports search and refresh, reconciles paths, and exposes Add to chat / Copy mention. File preview uses `@pierre/diffs` with virtualized file rendering and a worker-pool provider, plus Markdown/media modes. **For Brigadier:** file links in messages, tree selections, changed-file rows, and editor line references should all target the same file-surface operation. [Tree](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/files/FileBrowserPanel.tsx#L1), [preview](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/files/FilePreviewPanel.tsx#L1).

Diff selection distinguishes branch comparison, unstaged/working-tree selection, and individual turn checkpoints. The terminal surface has its own output synchronization, input and resize commands, mount/disposal lifecycle, and process status. **For Brigadier:** distinguish current Git state from changes attributed to a particular run; distinguish a live user terminal from a historical command-output card. [Diff scopes](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/DiffPanel.tsx#L174), [terminal surface](https://github.com/pingdotgg/t3code/blob/be7796d867a1e66524f19e6cfee0109c3ab447f0/apps/web/src/components/ThreadTerminalDrawer.tsx#L350).

## 4. Jan: polished thinking and tool presentation

Jan's chat is built from UIMessage parts; its separate Cowork types model user/assistant/tool entries with call IDs, arguments, live argument text, result/error/diff, and running/done state. Subagents carry their own run IDs and transcripts. This is useful evidence for a **typed widget vocabulary**, but Jan chat and Jan Cowork are distinct data models, not one interchangeable message schema. [Chat message renderer](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/containers/MessageItem.tsx#L145), [Cowork types](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/types/coworkSession.ts#L1).

The most useful interaction is `ChainOfThoughtGroup`: during streaming it shows the current meaningful step, follows the tool actually executing instead of the last queued call, offers an extended view, and renders a continuous reasoning/tool timeline after completion. A following answer normally collapses the trace. Pending approval steps remain visible so their controls cannot disappear. **For Brigadier:** a compact live status should reveal actual provider-emitted reasoning summaries/activity; do not manufacture hidden reasoning to fill the design. Preserve pending actions outside any disclosure that could hide them. [Thinking group](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/containers/message/ChainOfThoughtGroup.tsx#L32).

Tool cards have queued/running/waiting/failed/completed presentation. ToolCallCard selects document, terminal, workspace, or web widgets from native tool presentation metadata; generic tools retain expandable input/output. Input and results are not duplicated when the dedicated widget already displays them. **For Brigadier:** use a renderer registry keyed by normalized item kind, with one generic tool fallback. [Tool primitive](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/components/ai-elements/tool.tsx#L43), [widget selection](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/containers/message/ToolCallCard.tsx#L30).

CoworkAskCard docks above input and pages through multiple questions. Selection state resets on request-ID changes; every question must be answered; free text is exclusive with predefined options; decline cancels the request. **For Brigadier:** this is useful behavior for plan clarifications, separate from permission approvals. [Question card](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/containers/CoworkAskCard.tsx#L28).

Jan's basic reasoning component tracks streaming duration and renders a shimmer or completed duration label. Its richer group is the better behavioral reference, because duration and expansion are coordinated with tool work and following text. [Reasoning primitive](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/components/ai-elements/reasoning.tsx#L47).

## 5. Jan: useful boundaries and limitations

The session store owns Chat and transport objects by conversation ID, independently of mounted routes. Cowork also uses session-keyed maps and narrow active-session selectors. **For Brigadier:** keep session execution outside UI component lifecycle, and subscribe sidebar rows to a small status projection rather than every message delta. [Session store](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/stores/chat-session-store.ts#L14), [Cowork selectors](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/hooks/useCoworkRun.ts#L450).

Jan throttles chat updates to 50 ms, defers streaming Markdown with `useDeferredValue`, skips full-string LaTeX normalization during streaming, and postpones HTML artifact splitting until completion. However the chat route still renders `chatMessages.map` without a virtualized message list. **For Brigadier:** take the expensive-render boundaries, not that unbounded list. This is a structural observation, not a measured slowdown claim. [Throttle](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/routes/threads/$threadId.tsx#L305), [render mitigations](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/containers/RenderMarkdown.tsx#L216), [message list](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/routes/threads/$threadId.tsx#L1733).

Jan's composer uses an autosizing textarea (2–10 rows), attachment paste/drop, and IME-aware Enter handling. Its model/tool controls are tied to Jan's inference and tool ownership rather than CLI harness options. **For Brigadier:** useful input behaviors; T3 is the stronger reference for agent-dependent configuration and context chips. [Input](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/containers/ChatInput.tsx#L2100).

Cowork's side panel is a small resizable surface with local width state. Its diff panel groups recorded write/edit operations by file; the source explicitly distinguishes these sandbox edits from changes to an attached repository. This is not sufficient prior art for a full Git working-tree browser or terminal tab manager. [Panel](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/containers/CoworkSidePanel.tsx#L14), [diff semantics](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/containers/CoworkDiffPanel.tsx#L9).

Artifact previews are loaded separately from agent tool output: Cowork reads disk assets because tool results may truncate or describe files. HTML preview uses an opaque-origin sandboxed iframe, separate Code/Preview presentation, and a generated CSP; network access defaults off. **For Brigadier:** structured chat cards should use app-owned rendering. Arbitrary model HTML belongs in an isolated preview surface with no bridge to local command execution. This source observation is not a security certification. [Preview loader](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/containers/CoworkPreviewPanel.tsx#L35), [artifact component](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/components/HtmlArtifact.tsx#L11), [sandbox document](https://github.com/janhq/jan/blob/e2185dbc7db3a002da35b3688b57910ec6fd87b2/web-app/src/lib/htmlSandbox.ts#L1).

## Proposed Brigadier acceptance checks

These are recommendations, not claims that the current app passes them:

- Agent/model changes update the allowed controls and submitted native settings; saved values survive switching away and back. No local/remote selector exists.
- Draft text, context chips, attachments, undo, paste, IME composition, and send/stop behavior remain correct when a panel opens or the user switches threads.
- Tool deltas update stable items. Completed work can collapse; pending approvals/questions remain actionable. Reload reconstructs their actual state without duplicating actions.
- Streaming follows the bottom only while the user wants it; scrolling up and expanding cards preserve position. Long rich threads and large expanded tool groups keep bounded mounted content.
- File links and changed-file rows open the same file/line surface. File tree and Git changes refresh from local filesystem/repository state.
- Multiple user terminals remain attached to their native processes across panel hide/show and thread navigation. Closing a tab has explicit resource-lifecycle semantics.
- Unknown tool kinds render a useful generic card; unsupported CLI options are never presented as functional.
