## Provider input and fresh executions

**Documented and installed schema:** Codex `turn/steer` accepts `{threadId, expectedTurnId, input, clientUserMessageId?}` and returns `{turnId}`. No active turn or a mismatched expected id fails. It appends to current execution without a new `turn/started` and cannot override model/effort/permissions. Therefore queued Custom settings are used for later dispatch, while explicit steering necessarily targets the active execution's configuration. Receipt loss is uncertain delivery, never a reason for automatic replay. [Official app-server](https://learn.chatgpt.com/docs/app-server#steer-an-active-turn), generated `v2/TurnSteerParams.ts` and `TurnSteerResponse.ts`.

**Documented/source:** Codex `thread/start` creates fresh model history; `thread/resume`/`thread/fork` reuse it. `turn/start` can override model/effort/settings, which become defaults for later turns. To preserve the durable Brigadier session while discarding context, use a fresh provider start with Brigadier identity/event cursor supplied separately; merely injecting task checkpoints into a resumed native thread does not discard accumulated history. Model discovery is `model/list` with `supportedReasoningEfforts`; existing `codex/capabilities.rs` validates selections. [App-server](https://learn.chatgpt.com/docs/app-server), `crates/core/src/codex/mod.rs` and `capabilities.rs`.

**Documented/source:** Claude streaming input supports further user frames, sequential queueing, and interruption; current Brigadier `SendTurn` intentionally refuses while an authored turn is open. The wire permits user `priority` values and echoes message UUIDs, but a priority label alone is not proven acknowledged active steering. A verified interrupt-and-immediate-continue path is compatible; ordinary delayed queueing is not. [Streaming input](https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode), `crates/core/src/claude/adapter.rs`, existing `docs/research/agent-sdk.md` §2 and §10.

## Permissions: enforcement versus guidance

**Documented:** Claude `canUseTool` only sees calls that survive earlier auto-approval/rule decisions. `acceptEdits`, allow rules and bypass can skip that callback. `PreToolUse` runs before those decisions and is the correct interception seam for restrictions required on every invocation. `auto` is a native model classifier, not Brigadier's evidence/fusion protocol; `dontAsk` denies rather than implementing Full access. [Permission evaluation](https://code.claude.com/docs/en/agent-sdk/permissions), [approval callback](https://code.claude.com/docs/en/agent-sdk/user-input).

**Source:** current core hook policies enforce named tool/path/command gates, with documented limitations; they are not an OS sandbox. `HookPolicy` is synchronous, so independent model judgment must not block inside it. Return an ask decision and resolve the resulting parked ApprovalTable request asynchronously in the host. Explicit restrictions must run before any authorization shortcut. `crates/core/src/claude/hook.rs`, `crates/core/src/approval.rs`.

**Source/inference:** ask/approve/full must remain Brigadier vocabulary. Ask routes required approval to owner; Approve routes the same requests through a bounded, cancellable host adjudicator with real task authorization and independent read-only judgment where useful, escalating insufficient evidence; Full uses supported no-prompt provider settings while retaining explicit restrictions. Mapping approve to acceptEdits or auto alone fails that contract. Codex sandbox, native permission requests and optional native reviewer are separate controls. `crates/core/src/codex/mod.rs::permission`, `adapter.rs::approval`, installed `ApprovalsReviewer.ts`.

**Source:** supervisor `ModelCall` already supports one-turn disposable sessions and read-only hooks. The interactive peer path's orchestration prompt is guidance; it is not deterministic review/fusion enforcement. Host adjudication must use actual independent calls and consume structured decisions rather than claim a prompt instruction guaranteed them. `crates/supervisor/src/loop_/call.rs`, `src-tauri/src/peers.rs`, `docs/plans/brigadier-20260909/RECOVERY-REVIEW.md`.

No claim here establishes that free-text restrictions can be perfectly mechanically interpreted. Native sandbox/rules and explicit parsed restrictions can be enforced; natural-language authorization judgment remains fallible and must escalate unresolved cases.


## Implemented slice and verification

**Source, this worktree:** core now has Brigadier `Ask`/`Approve`/`Full` policy variants and a fresh `StartSession.resumed` identity/cursor independent of provider resume tokens. Codex implements acknowledged `turn/steer` through `NativeControl::Steer`; Claude explicitly requires the host's interrupt-and-continue route. Claude per-execution approval/anonymous/stream counters seed from the persisted event cursor so renewed native contexts cannot reuse earlier durable identifiers. Ask/Approve intercept unknown/external tools as well as mutation tools; Full suppresses permission prompts while retaining the harness's nested-provider refusal. Existing legacy policies retain their compatibility behavior.

**Source:** `src-tauri/src/approval_policy.rs` is the asynchronous host broker. Two fresh independent calls analyze authentic durable owner instructions (including parent authorization for peers), never model-written checkpoints as authority. Supported verbatim evidence plus agreement can authorize; conflicting/incomplete evidence escalates. The two calls use different registered providers when available, otherwise independent fresh calls on one provider; cross-model diversity is not guaranteed. Journals persist before review and response; restart does not retry an ambiguous decision. Review startup, submission and streaming are bounded/cancellable; native processes are tracked and killed. A response submission does not replace provider `RequestResolved` confirmation.
